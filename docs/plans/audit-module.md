# План: модуль «Аудит» — безпека і стан системи

Статус: **затверджено 2026-10-27** з рекомендаціями за замовчуванням з розділу 9. Реалізуємо поетапно
(фази в розділі 8), кожна фаза — окремий коміт. Фаза 0 — готово (v0.2.0). Фази 1–2 — готово.
Реліз — один, коли будуть готові всі фази (рішення 2026-10-27).

Фаза 2, що додалося понад план:
- Служби й завдання з правами SYSTEM перевіряються на права запису (ACL): чи може звичайна програма замінити їхній
  exe (високий ризик) або покласти файли в їхню папку (середній). Типовий випадок — лаунчери ігор на другому диску.
- Програми віддаленого доступу (TeamViewer, AnyDesk…) — окрема перевірка: ними користуються шахраї.
- Рецепт `remote-registry-off`.

Відхилення від плану у Фазі 1:
- Замість одного рецепта `security-core` — окремі `hvci`, `lsa-protection`, `driver-blocklist` (+ профіль `security`):
  у кожного свої мінуси, і користувач має вмикати їх незалежно (наприклад, LSA так, HVCI ні — через FPS).
- Рецепта `autologon-password-remove` немає: бекап Setup зберіг би пароль відкритим текстом у `data\setup`.
  Перевірка радить netplwiz або Sysinternals Autologon.
- Kernel DMA Protection перенесено на пізніше: без прав адміністратора надійно не читається.

## 1. Мета простими словами

DEADPIXEL зараз відповідає на питання «чому ПК впав». Модуль «Аудит» відповідає на інше:
**«де в моїй системі діри і що з ними робити»** — без потреби бути фахівцем з безпеки.

Для кожної знахідки користувач бачить:

- **що не так** — одним реченням, без жаргону;
- **наскільки це небезпечно** — рівень (критично / високо / середньо / низько / інфо) і чому саме такий;
- **плюси і мінуси** змін — наприклад, HVCI захищає ядро, але може зняти кілька % FPS і не працює зі старими драйверами;
- **що зробити** — кнопка «Виправити» (через Setup з відкатом), «Відкрити налаштування Windows» або покрокова інструкція;
- **«Ігнорувати»** — якщо це свідомий вибір (наприклад, RDP потрібен), знахідка більше не турбує.

## 2. Головні принципи (не обговорюються)

1. **Аудит нічого не змінює.** Він лише читає систему. Усі зміни — через наявний модуль Setup
   (рецепти з бекапом і відкатом, прибирання хвостів — через карантин). Одне місце, де щось змінюється,
   = менше шансів зламати систему.
2. **Окремий процес, не в треї.** Трей лишається легким (зараз ~0.7% ядра). Аудит запускається
   кнопкою або за розкладом і завершується після сканування. У фоні він не займає нічого.
3. **Усе локально.** Нічого не надсилається в мережу. Єдиний виняток — перевірка оновлень програм
   через `winget` (звертається до каталогу Microsoft), і її можна вимкнути.
4. **Без фальшивих тривог.** Кожна перевірка має пояснення «чому це проблема». Евристики
   («підозрілий процес») позначені як *підозра*, а не вирок, і показують докази.
5. **Чесні плюси/мінуси.** Програма не тисне «увімкни все». Наприклад, деякі ігри *вимагають* Secure Boot/TPM,
   а HVCI може конфліктувати зі старими драйверами — це пишемо прямо.

## 3. Архітектура

```
modules/
  setup/                   ← як є: рецепти, бекап, відкат (сюди додаємо нові рецепти безпеки)
  audit/
    Audit.ps1              ← рушій: запускає перевірки, рахує оцінку, пише JSON
    Audit.cmd              ← запуск з консолі (як Setup.cmd)
    checks/<область>.ps1   ← перевірки, згруповані за областями (див. розділ 4)
    gui/AuditGui.cs        ← вікно (збирається build.cmd, ділить Theme.cs з треєм)
data/audit/                ← (у .gitignore через data/) звіти, історія, список ігнорованого
  latest.json, report-YYYYMMDD-HHmm.json, ignore.json
```

**Формат перевірки** (так само просто, як рецепти Setup):

```powershell
@{
    Id       = 'hvci'
    Area     = 'platform'
    Title    = 'Цілісність пам''яті (Memory Integrity / HVCI)'
    Admin    = $false                       # чи потрібні права адміністратора для точного результату
    Test     = { ... }                      # повертає 0..N знахідок (або нічого = все гаразд)
    Explain  = 'Що це і навіщо — 2-3 речення простою мовою'
    Pros     = @('Шкідливий драйвер не зможе змінити ядро', ...)
    Cons     = @('−1…5% FPS у деяких іграх', 'Старі драйвери можуть не завантажитись', ...)
    Fix      = @{ Recipe = 'security-hvci' }  # або Open = 'windowsdefender://coreisolation', або Steps = @(...)
}
```

**Знахідка** = `Id, Severity, Title, Detail, Evidence (докази: шлях, порт, версія…), Fix, Confidence (точно/підозра)`.

**Оцінка ризику**: 0–100 загалом і по кожній області. Критична знахідка «важить» набагато більше
за кілька дрібних, щоб 20 інфо-пунктів не ховали одну справжню діру. Ігноровані знахідки не рахуються.

**Права**: без адміна аудит працює, але частину перевірок позначає «потрібні права»
(BitLocker, Secure Boot, частина служб). Кнопка «Сканувати з правами» = один UAC.
Запуск за розкладом іде через Планувальник завдань з найвищими правами — UAC лише раз, під час налаштування розкладу.

**Розклад**: завдання Планувальника «DEADPIXEL Audit» — раз на N днів (типово 3), коли ПК простоює,
з низьким пріоритетом CPU/диска. Трей раз на хвилину дивиться дату `latest.json` (одна дешева операція)
і показує сповіщення лише про **нові** критичні/високі знахідки з минулого сканування.

## 4. Що перевіряємо (за областями)

### 4.1 Захист платформи (залізо + ядро)
| Перевірка | Чому важливо | Виправлення |
|---|---|---|
| Secure Boot | Без нього буткіт може завантажитись раніше за Windows; деякі ігри (анти-чит) його вимагають | інструкція для BIOS (сценарій Setup з перезавантаженням у UEFI) |
| TPM (є / версія / готовий) | Потрібен для BitLocker, Windows Hello, Windows 11 | інструкція для BIOS (fTPM/PTT) |
| Memory Integrity (HVCI), VBS | Захист ядра від шкідливих драйверів. Мінус: −FPS, несумісні драйвери | рецепт Setup + **список драйверів, що заважають**, якщо Windows їх повідомляє |
| Блок-лист вразливих драйверів | Блокує відомі драйвери, якими атакують ядро | рецепт Setup |
| Захист LSA (RunAsPPL) | Ускладнює крадіжку паролів із пам'яті | рецепт Setup |
| Credential Guard | Те саме, сильніше (лише Pro/Enterprise) | інфо + рецепт |
| Kernel DMA Protection | Захист від атак через Thunderbolt/USB4 | лише інфо (залежить від заліза) |
| Шифрування диска (BitLocker / Device Encryption) | Вкрадений ноутбук = вкрадені дані | інструкція; **попередження про ключ відновлення** |
| Режим завантаження UEFI vs Legacy, вік BIOS | Старий BIOS = відомі вразливості та проблеми стабільності | інфо + посилання на сайт виробника плати |

### 4.2 Захист Windows
Defender (реальний час, вік сигнатур, Tamper Protection, захист від PUA), SmartScreen,
брандмауер (усі профілі увімкнені), рівень UAC, Windows Update (останнє встановлення, призупинення, чи чекає перезавантаження),
**версія Windows і кінець підтримки** (наприклад, Windows 10 без ESU після жовтня 2025 = критично).

### 4.3 Мережа і відкриті порти
- Усі **слухаючі порти** TCP/UDP → який процес, яка програма, підписана чи ні.
- Головне розрізнення: слухає **лише цей ПК** (127.0.0.1) — нормально; слухає **всю мережу** (0.0.0.0) — дивимось далі,
  чи дозволяє це брандмауер.
- Відомі ризиковані порти/служби: SMB 445, RDP 3389, VNC 5900, Telnet 23, FTP 21, NetBIOS 135/139, UPnP.
- SMBv1 (через нього поширювався WannaCry), RDP без NLA, віддалений реєстр, профіль мережі «Приватна» у публічному Wi-Fi.
- Кожен порт має людський опис: «Steam — завантаження ігор від друзів у локальній мережі, нормально».
  Вбудований довідник відомих програм/портів, щоб не лякати звичними речами.

### 4.4 Процеси і автозапуск (пошук підозрілого)
Евристики — кожна дає «бали підозри», показуємо докази, а не вирок:
- exe запущено з `%TEMP%`, `Downloads`, `AppData\Roaming`, кореня `ProgramData`;
- **без цифрового підпису** або з недійсним підписом;
- маскування під системні: `svchost.exe` не з `System32`, схожі імена (`scvhost`, `expl0rer`);
- дивні батьки: Word/браузер → PowerShell/cmd; PowerShell із закодованою командою (`-enc`);
- приховане вікно + мережеві з'єднання.

Автозапуск: ключі Run/RunOnce, папка «Автозавантаження», **завдання Планувальника** не від Microsoft,
служби не від Microsoft (особливо зі шляхом у папці, куди може писати користувач, або «unquoted path»),
WMI-підписки, IFEO debugger. Кнопка «Перевірити Defender'ом» для конкретного файлу — локально, нічого не вивантажує.

Перевірку підписів кешуємо (шлях + час зміни файлу), тож повторні сканування швидкі.

### 4.5 Програми і драйвери
- **Застарілі програми**: список встановленого + `winget upgrade` (якщо дозволено) → «є новіша версія».
- Окремо підсвічуються **критичні застарілі**: браузери, Java, Adobe Reader, 7-Zip/WinRAR (відомі вразливості архіваторів),
  старі рантайми (Python 2, .NET Core без підтримки), програми, які більше не підтримуються.
- **Драйвери**: непідписані, дуже старі (>5 років), відомі проблемні; зв'язок із крашами, які DEADPIXEL уже бачить.

### 4.6 Облікові записи
Скільки адмінів, увімкнений «Гість» / вбудований Administrator, записи без пароля,
**пароль автовходу збережений у реєстрі відкритим текстом** (Winlogon `DefaultPassword`) — критично.

### 4.7 Стан системи (не безпека, але «діри» стабільності)
Мало місця на системному диску, вимкнені точки відновлення, немає резервних копій, ПК давно не перезавантажувався
і чекає перезавантаження, стан дисків (уже є в DEADPIXEL — беремо звідти).
Важкі перевірки (`sfc /scannow`, `DISM /RestoreHealth`) — **лише кнопкою**, не за розкладом.

### 4.8 «Хвости» видалених програм
Чесно одразу: **більшість хвостів у реєстрі безпечні** — це кілобайти, які нічого не сповільнюють.
«Чистильники реєстру», що масово видаляють тисячі ключів, частіше ламають систему, ніж допомагають.
Тому шукаємо не «все сміття», а хвости, які **реально важливі**, і ділимо їх на три групи:

**Небезпечні (можуть стати дірою)** — це те, що варто прибрати:
| Хвіст | Чому небезпечно |
|---|---|
| **Служба, чий exe уже видалено**, а шлях веде в папку, куди може писати користувач | Будь-яка програма може покласти туди свій файл, і Windows запустить його **з правами SYSTEM** під час старту |
| **Завдання Планувальника на неіснуючий файл** | Та сама схема: підкласти файл → він запускається за розкладом |
| **Драйвер, що лишився після видалення програми** (старі утиліти розгону, моніторингу, анти-чити) | Старі драйвери часто мають відомі вразливості, і ними атакують ядро. Окремо перевіряємо за блок-листом вразливих драйверів |
| **Записи в `PATH` на неіснуючі папки** в профілі користувача | Підміна програм: створюєш папку → твій `git.exe` запускається замість справжнього |
| **Правила брандмауера для програм, яких уже немає** | Дозвіл на вхідні з'єднання лишається; якщо файл з'явиться знову, порт буде відкритий |

**Ламають роботу, але не небезпечні:**
- розширення контекстного меню / Провідника на видалені DLL — гальма або падіння Провідника;
- записи в «Програмах і компонентах», які не видаляються (деінсталятор зник);
- автозапуск (Run, «Автозавантаження») на неіснуючий файл — помилки під час входу.

**Просто займають місце:**
- папки в `Program Files`, `ProgramData`, `AppData` від програм, яких уже немає. Показуємо розмір і впевненість
  («точно від видаленої програми» / «можливо»). Великі кеші (`npm`, `pip`, ігрові лаунчери) — окремо;
- старі пакети драйверів у сховищі драйверів (наприклад, десятки старих версій NVIDIA — це гігабайти).

**Як прибираємо** — тут аудит уперше щось видаляє, тому обережно:
- лише після підтвердження, і лише те, що користувач позначив;
- **спершу карантин**: папки переносяться в `data/quarantine/`, ключі реєстру експортуються в `.reg`,
  служби й завдання зберігаються для відновлення. Кнопка «Відновити» повертає все як було;
- через 30 днів карантин можна очистити кнопкою, і лише тоді файли видаляються остаточно;
- системні шляхи (`Windows`, `System32`, драйвери Microsoft) — у «білому списку», їх не чіпаємо ніколи.

Технічно це новий тип дії в рушії Setup (`Cleanup` з карантином) — той самий принцип, що й бекап/відкат рецептів.

## 5. Вікно (AuditGui.exe, пункт трея «Аудит системи…»)

- **Вгорі**: загальна оцінка (0–100, колір), дата останнього сканування, «Сканувати зараз», «Розклад…».
- **Картки областей**: Платформа · Windows · Мережа · Процеси · Програми · Облікові записи · Стан — у кожній кількість проблем за кольором.
- **Список знахідок**: спершу найнебезпечніші; фільтр «лише нове з минулого разу».
- **Панель деталей**: «Що це», «Чому це важливо», **Плюси / Мінуси**, докази, кнопки
  «Виправити» (відкриває рецепт Setup) / «Відкрити в Windows» / «Ігнорувати» / «Перевірити Defender'ом».
- **Експорт HTML-звіту** — щоб показати комусь, хто розбирається.

Стиль — та сама тема, що й у DEADPIXEL і Setup. Спільні елементи вікна виносимо зі `SetupGui.cs` у спільний файл,
щоб не копіювати код.

## 6. Нові рецепти Setup (для кнопок «Виправити»)

`security-core` (HVCI, блок-лист вразливих драйверів, LSA), `smb1-off`, `rdp-hardening` (NLA або вимкнути),
`defender-hardening` (PUA, мережевий захист), `uac-default`, `autologon-password-remove`.
Усі — з перевіркою, бекапом і відкатом, як наявні рецепти. Для HVCI — попередня перевірка несумісних драйверів
**перед** увімкненням, щоб ПК не перестав завантажуватись.

## 7. Пакування і автоматичні релізи на GitHub

**Так, це реально і недорого**, бо проєкт уже збирається компілятором, який є в кожній Windows, без Visual Studio.
GitHub Actions має готові Windows-машини з тим самим компілятором, тож `build.cmd` там працюватиме як у тебе.

**Як це виглядає для тебе:**
1. Пишеш код, комітиш як зараз.
2. Коли хочеш реліз, ставиш тег версії (`git tag v0.2.0 && git push --tags`) або натискаєш кнопку в GitHub.
3. GitHub сам збирає програму і публікує сторінку релізу з файлами та списком змін.

**Що буде в релізі:**
| Файл | Для кого |
|---|---|
| `DEADPIXEL-0.2.0-setup.exe` | Звичайний інсталятор: «Далі → Далі → Готово» |
| `DEADPIXEL-0.2.0-portable.zip` | Розпакував і запустив, нічого не встановлюючи |
| `SHA256SUMS.txt` | Контрольні суми, щоб перевірити, що файл не підмінили |

**Інсталятор** (Inno Setup — безкоштовний, стандарт для таких програм):
- встановлення **для поточного користувача** в `%LOCALAPPDATA%\Programs\DEADPIXEL` — **без прав адміністратора**.
  Дані тоді лежать поруч із програмою, як зараз;
- ярлик у «Пуск» (і за бажанням на робочому столі), галочка «Запускати з Windows»;
- оновлення поверх старої версії: інсталятор сам попросить закрити DEADPIXEL (він бачить, що програма запущена);
- видалення питає «Видалити також зібрані дані?» і прибирає завдання Планувальника, автозапуск і ярлики —
  щоб **сам DEADPIXEL не лишав хвостів**, які ми шукаємо в інших програмах.

**Версії**: одна версія на все (`0.2.0`), вшивається в exe (видно у «Властивостях» файлу й у панелі програми),
плюс `CHANGELOG.md` — що змінилося в кожній версії. Сторінка релізу заповнюється з нього.

**Перевірка кожного коміту**: GitHub збирає проєкт і на звичайних комітах — якщо щось не компілюється
або рецепт/перевірка має синтаксичну помилку, видно одразу, ще до релізу.

**Що треба знати про цифровий підпис** — єдина реальна складність:
- Без підпису Windows при першому запуску покаже синє вікно SmartScreen «Windows захистила ваш ПК»
  (→ «Докладніше» → «Усе одно запустити»). Це нормально для нових програм без підпису, але відлякує.
- Деякі антивіруси можуть **помилково** підозрювати DEADPIXEL: він читає процеси, активне вікно, події системи,
  запускає PowerShell — схоже на поведінку шпигунських програм. Підпис і відкритий код сильно зменшують це.
- Варіанти: **починаємо без підпису** (контрольні суми + відкритий код на GitHub + за потреби подаємо файл
  у Microsoft на перевірку хибного спрацювання); пізніше — **SignPath Foundation** (безкоштовний підпис
  для open-source, потрібна заявка) або платний сертифікат (від ~$10/міс через Microsoft Artifact Signing,
  якщо доступно в твоїй країні, або ~$200+/рік класичний).

**Перевірка оновлень у програмі** (за бажанням): раз на день питати GitHub «чи є новіша версія» і показувати
кнопку «Завантажити». Це звернення в інтернет, тому — лише якщо ввімкнеш (типово вимкнено).

## 8. Фази реалізації

| Фаза | Що входить | Результат |
|---|---|---|
| **0. Пакування і релізи** | версія в exe, `CHANGELOG.md`, GitHub Actions (збірка на кожен коміт + реліз за тегом), інсталятор, portable zip | Перший реліз `v0.2.0` на GitHub; далі кожна фаза виходить сама |
| **1. Каркас + платформа** | рушій `Audit.ps1`, формат перевірок/знахідок, оцінка, JSON; області 4.1, 4.2, 4.6; AuditGui з панеллю плюсів/мінусів; рецепт `security-core`; пункт у треї | Видно HVCI, Secure Boot, TPM, Defender тощо з поясненнями, і можна виправити |
| **2. Мережа + процеси** | 4.3 і 4.4, довідник відомих портів/програм, кеш підписів, «Перевірити Defender'ом»; рецепти `smb1-off`, `rdp-hardening` | Видно відкриті порти та підозрілі процеси/автозапуск |
| **3. Програми + розклад** | 4.5, 4.7, Планувальник, сповіщення в треї про нове, порівняння з минулим скануванням, HTML-експорт | Аудит сам запускається раз на N днів і повідомляє лише про нове |
| **3.5 Хвости програм** | 4.8: пошук небезпечних/зламаних хвостів, розмір «сміття», прибирання через карантин з відновленням | Видно, що лишилось після видалених програм, і це можна безпечно прибрати |
| **4. Пізніше (за бажанням)** | розширення браузерів, налаштування приватності, перевірка паролів Wi-Fi-мереж тощо | — |

**Критерії готовності кожної фази**: сканування без прав адміна працює і не падає; повне сканування < 60 с
(крім `winget`); на чистій Windows немає фальшивих «критичних»; кожна знахідка має пояснення і дію;
трей у фоні не стає важчим.

## 9. Питання до тебе перед стартом

1. **Окреме вікно `AuditGui.exe`** (рекомендую) чи вкладка в наявному вікні Setup?
2. **`winget` для перевірки оновлень** — дозволяємо (звертається в інтернет до каталогу Microsoft) чи лише локальний список версій?
3. **Розклад за замовчуванням** — раз на 3 дні, коли ПК простоює? Чи вимкнений, поки не ввімкнеш?
4. **Назва в меню** — «Аудит системи», «Перевірка безпеки» чи інша?
5. **Сповіщення з розкладу** — лише про критичні, чи також про високі?
6. **Перевірка оновлень DEADPIXEL** через GitHub — потрібна (типово вимкнена) чи взагалі не робимо?
7. **Перша версія** — `v0.2.0` (рекомендую: проєкт робочий, але ще росте) чи одразу `v1.0.0`?

**Рішення (затверджено):** окреме вікно · `winget` дозволено · раз на 3 дні · «Аудит системи» ·
критичні + високі · перевірка оновлень є, але вимкнена · `v0.2.0`. Порядок робіт: Фаза 0 → 1 → 2 → 3 → 3.5.

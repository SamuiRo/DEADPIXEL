# DEADPIXEL

**Українська** · [English](README.md)

Діагностика аварійних перезавантажень, зависань відеодрайвера та проблем із дисками в Windows 10/11 — а також
аудит безпеки і стану системи та налаштування ПК за рецептами, які можна відкотити.

## Що входить

| Файл | Призначення |
|---|---|
| `DeadPixel.exe` | Трей-програма з панеллю: живі показники GPU/CPU, «чорна скринька», краші з таймлайном, аналіз дампів (WinDbg), закономірності, історія змін драйверів/оновлень, диски (SMART, детектор зависань), процеси, пакет для діагностики |
| `DeadPixel.ps1` / `DeadPixel.cmd` | Разовий HTML/TXT-звіт за N днів (`DeadPixel.cmd -Days 60`) |
| `src/` | Вихідний код трей-програми (C# 5, .NET Framework 4.5+) |
| `build.cmd` | Збірка `DeadPixel.exe` і GUI модулів компілятором, що є в Windows — без Visual Studio і SDK |
| `modules/` | Модулі на вимогу — окремі процеси, які трей лише запускає: `audit` (аудит) і `setup` (рецепти, карантин) |
| `linux/audit.sh` | Аудит безпеки для Linux-машин одним файлом (Debian/Ubuntu, Arch, Fedora) |
| `installer/`, `tools/Package.ps1` | Інсталятор Inno Setup і збирання релізу (zip, інсталятор, контрольні суми) |
| `CHANGELOG.md` | Що змінилося у версіях |

## Як користуватися

**Встановлення.** Зі сторінки [Releases](https://github.com/SamuiRo/DEADPIXEL/releases) візьміть інсталятор
(ставиться для поточного користувача, прав адміністратора не просить) або portable-архів — розпакуйте в будь-яку
папку й запустіть `DeadPixel.exe`. Цифрового підпису програма поки не має, тому SmartScreen під час першого запуску
покаже попередження: «Докладніше» → «Усе одно запустити». Цілість файлів перевіряється за `SHA256SUMS.txt`.

**Перший запуск.** У треї з'являється іконка-піксель: помаранчева — усе гаразд, жовта — попередження, червона —
новий збій, якого ви ще не бачили. Меню іконки: «Відкрити панель», «Аудит системи…», «Сетап ПК (рецепти)…»,
«Налаштування…». У налаштуваннях варто одразу ввімкнути «Запускати разом із Windows»: чорна скринька корисна лише
тоді, коли пишеться постійно.

**ПК зависає, гасне екран або він перезавантажується:**
1. Лишіть DEADPIXEL працювати у фоні — він раз на кілька секунд записує стан GPU і CPU та стежить за журналами Windows.
2. Після збою відкрийте панель → «Краші»: що відбувалося в останні хвилини перед кожним збоєм. «Аналіз» шукає
   закономірності, «Зміни» показує, які драйвери й оновлення ставилися перед тим, як почалися проблеми.
3. Синій екран або зависання відеодрайвера — «Аналізувати дамп BSOD» / «Аналізувати дамп TDR» на вкладці «Краші»
   (потрібен WinDbg; програма запропонує його встановити).
4. «Сетап ПК» → профіль «Стабільність»: налаштування живлення шини PCIe і дисків та сценарії для відеокарти
   (чиста установка драйвера, тест живлення, BIOS).
5. Потрібна допомога іншої людини — «Зібрати пакет для діагностики» внизу панелі: один архів зі звітом і дампами.

**Перевірити безпеку ПК:**
1. Трей → «Аудит системи…» → «Сканувати». Для повної картини — «Сканувати з правами».
2. Ідіть списком згори (найнебезпечніше перше). Для кожної знахідки написано, що це, плюси й мінуси виправлення
   і докази.
3. «Виправити…» відкриває рецепт у «Сетапі ПК»: там видно, що саме зміниться, і є «Відкотити». «Відкрити в Windows»
   веде в потрібне вікно налаштувань. Те, що ви лишаєте свідомо, — «Ігнорувати».
4. Хвости видалених програм, драйвери античітів, сліди зламу — «Прибрати…»: вибране переноситься в карантин,
   звідки його можна повернути («Карантин…»).
5. «Розклад…» вмикає автоматичне сканування раз на кілька днів; трей повідомить лише про нові серйозні знахідки.

**Налаштувати новий ПК або посилити захист** — «Сетап ПК» → профіль («Новий ПК», «Безпека», «Стабільність»,
«Діагностика крашів») → «Перевірити» покаже, що відрізняється від рекомендованого → «Застосувати». Старі значення
зберігаються, «Відкотити» повертає саме їх. Перед застосуванням прочитайте мінуси в підказках: частина захисту
(Memory Integrity, правила ASR) може заважати старим драйверам і програмам.

**Linux-машини** — скопіюйте `linux/audit.sh` на машину і запустіть `sudo ./audit.sh --lang uk`. Скрипт лише читає
систему.

**Видалити DEADPIXEL** — «Налаштування → Видалити DEADPIXEL…» (докладніше — розділ «Видалення»).

## Модулі

Важке або разове не живе в трей-програмі постійно: кожен модуль — окрема програма/скрипт у `modules/<назва>/`,
яку запускає пункт меню трея (`TrayApp.RunModule`) або яку можна запустити напряму.

### Audit — перевірка безпеки і стану системи

**GUI** — `modules/audit/AuditGui.exe` (пункт трея «Аудит системи…»): загальна оцінка 0–100, картки областей,
список перевірок від найнебезпечнішої, а для вибраної — що це, плюси, мінуси, докази і що зробити.
«Виправити…» відкриває відповідний рецепт Setup (там видно зміни і є відкат), «Відкрити в Windows» — потрібне вікно
налаштувань, «Перевірити Defender'ом» — перевірка підозрілих файлів (без видалення), «Ігнорувати» — свідомий вибір,
який більше не рахується в оцінці.

Області: захист платформи (UEFI, Secure Boot, TPM, VBS, цілісність пам'яті, LSA, блок-лист вразливих драйверів,
політики App Control і Smart App Control, шифрування диска, вік BIOS), захист Windows (антивірус, брандмауер, UAC,
SmartScreen, оновлення), облікові записи, мережа (хто приймає з'єднання і чи пропускає брандмауер),
процеси й автозапуск (підозрілі процеси, автозавантаження, Планувальник, служби з файлами, які може замінити будь-яка
програма, IFEO, WMI), програми й драйвери (версії з відомими вразливостями, застарілі версії через winget, програми
без підтримки, драйвери),
стан системи (місце, диски, перезавантаження, точки відновлення), хвости програм (служби, завдання, драйвери, PATH,
брандмауер, автозапуск, контекстне меню, записи «Програм», папки без програми, старі драйвери в сховищі).

Ще п'ять областей закривають те, чого антивірус сам не закриває:
- **Посилений захист** — правила зменшення поверхні атаки (ASR), мережевий захист Defender, захист папок від
  програм-вимагачів, винятки антивіруса, давність повного сканування, Windows Script Host. Рецепти: `asr-rules`,
  `network-protection`, `script-host-off`.
- **Паролі й секрети** — що з ПК забере викрадач паролів: паролі й картки, збережені в браузерах (Chromium і Firefox;
  читаються лише адреси сайтів і кількість, бази відкриваються тільки для читання вбудованою `winsqlite3.dll`),
  розширення браузерів із доступом до всіх сайтів, токени у відкритих файлах (`.aws\credentials`, `.npmrc`,
  `.git-credentials`, Docker, rclone…), ключі SSH без пароля, секрети у змінних середовища, файли на кшталт «паролі.txt».
  Значення секретів не читаються і у звіт не потрапляють — лише імена файлів і змінних.
- **Розробка й ШІ-агенти** — ланцюг постачання пакетів і агенти, які самі запускають команди: скрипти встановлення
  npm/pnpm, затримка для свіжих версій пакетів, режими без підтвердження в Claude Code і Codex, автозапуск завдань
  у VS Code/Cursor, сервери MCP без зафіксованої версії, невидимі символи в правилах і навичках агентів, команди
  в глобальному `.gitconfig`. Рецепт: `npm-hardening`. Читаються лише файли налаштувань, нічого не запускається.
- **Ігри й емулятори** — античіти рівня ядра (які драйвери лишилися, що працює зараз, як прибрати) і хвости
  емуляторів: драйвери гіпервізора, служби, автозапуск, папки з віртуальними дисками. Запис служби чи драйвера
  зі списку античітів та емуляторів прибирається через карантин, якщо він зараз не працює. Служби читаються з реєстру
  напряму, тож видно й записи, яких не показують ні «Служби», ні `sc`, — типовий хвіст драйвера видаленої гри.
- **Сліди зламу** — індикатори відомих інцидентів (список у `checks/threats.ps1`, поповнюється з релізами; перший —
  злам лаунчера NIKKE 2026), перехоплення COM-компонентів у розділі користувача, програми без підпису в профілях
  браузерів, файл hosts, системний проксі, сторонні кореневі сертифікати, програми, що здають ПК як проксі-вузол,
  і пересилання трафіку через ПК.

**Linux** — `linux/audit.sh`: той самий підхід одним файлом без залежностей (оновлення, SSH, брандмауер, порти,
облікові записи, параметри ядра, автозапуск, токени, npm і ШІ-агенти). Лише читає систему:
`./audit.sh`, `sudo ./audit.sh` (повніше), `--lang uk`, `--json звіт.json`, `--area ssh`, `--list`.

**Прибирання хвостів — лише через карантин.** Аудит нічого не видаляє: «Прибрати…» передає вибране рушію Setup
(`Setup.ps1 -Cleanup`, з UAC). Перед кожною дією рушій ще раз перевіряє, що ціль досі «хвіст» і лежить у дозволеному
місці, а тоді переносить її в `data\quarantine\<дата>`: файли й папки — фізично, розділи реєстру й служби — в .reg,
завдання — в XML, правила брандмауера — з усіма параметрами. «Карантин…» (або `Setup.ps1 -Quarantine`,
`-Restore <сесія>`) повертає все на місце; `-Purge <сесія>` видаляє остаточно, але не раніше ніж через 30 днів.
Ніколи не чіпає: папку Windows, корені Program Files/ProgramData/AppData, папки Microsoft і працюючих програм,
розділи реєстру поза записами «Програм» і обробниками контекстного меню, завдання з `\Microsoft\`.
Для «Слідів зламу» є окремий вузький дозвіл: COM-запис у розділі користувача (`HKCU\Software\Classes\CLSID\{…}`),
окремий файл поза Windows і Program Files, папка всередині папки програми в AppData.
Запис драйвера чи служби, файл якої ще на місці, прибирається лише для імен зі списку античітів та емуляторів
і лише коли драйвер не працює.

**Розклад** — «Розклад…»: завдання Планувальника `\DEADPIXEL\DEADPIXEL Audit` запускає `AuditGui.exe --background`
раз на N днів (без вікон, низький пріоритет, з правами звичайного користувача — exe лежить у папці, куди можна писати,
тож запускати його з правами адміністратора за розкладом було б дірою). Завдання створюється без UAC (UAC потрібен лише
щоб замінити завдання, створене старою версією з правами адміністратора). Без прав не видно чужих процесів і підписок
WMI — такі перевірки позначаються як неповні. Вимкнення розкладу прибирає і завдання, і папку `\DEADPIXEL`.
Трей раз на хвилину дивиться `data\audit\summary.ini` і повідомляє лише про **нові** критичні й високі проблеми;
клік відкриває аудит на цій перевірці. Вимкнути — «Налаштування → Сповіщення» в панелі.
**«Звіт HTML»** зберігає сторінку в `reports\` — вона містить відомості про ПК, показуйте її лише тим, кому довіряєте.
**winget** (перевірка оновлень програм) звертається до каталогу Microsoft в інтернеті; решта аудиту працює офлайн.

**Аудит нічого не змінює** — він лише читає систему. Більшість перевірок працює без прав адміністратора;
без них не видно чужих і системних процесів та підписок WMI — тоді з'являється «Сканувати з правами».
Повне сканування триває близько хвилини. Звіти — у `data\audit\` (`latest.json`, `history\`, `ignore.json`;
`sigcache.json` — кеш перевірених цифрових підписів, щоб повторні сканування були швидкими).

**Консоль** — `modules/audit/Audit.cmd` (з правами, зберігає звіт) або напряму:

```bat
powershell -File Audit.ps1                      :: усі перевірки; код виходу = кількість критичних і високих
powershell -File Audit.ps1 -Area platform       :: одна область (platform, windows, hardening, accounts, secrets, devtools, network, processes, threats, software, health, leftovers, gaming)
powershell -File Audit.ps1 -Html report.html    :: останній звіт як HTML
powershell -File Audit.ps1 -Schedule 3          :: автоматично раз на 3 дні; 0 — вимкнути
powershell -File Audit.ps1 -Check hvci,uac      :: окремі перевірки
powershell -File Audit.ps1 -Save                :: зберегти як останній звіт (лише повне сканування)
powershell -File Audit.ps1 -Ignore guest        :: не рахувати знахідку; -Unignore повертає
```

**Нова перевірка** — запис у `modules/audit/checks/<область>.ps1` (UTF-8 з BOM):

| Поле | Що це |
|---|---|
| `Id`, `Title` | ідентифікатор (для ігнорування) і назва |
| `Test` | скриптблок; повертає `Ok 'значення'`, `Issue <critical\|high\|medium\|low\|info> 'значення' 'пояснення' @(докази) @(файли)`, `Unknown '…'` або `NotApplicable '…'`; `Limited (…)` — результат неповний без прав адміністратора. Файли з п'ятого аргументу GUI пропонує перевірити Defender'ом |
| `Explain`, `Pros`, `Cons` | що це простою мовою; плюси і мінуси увімкнення |
| `Fix` | `@{ Recipe = 'рецепт Setup'; Open = 'ms-settings:…'; Steps = @('вручну…') }` |
| `Admin` | `$true` — без прав адміністратора перевірка не запускається |
| `Prepare` | необов'язковий скриптблок, що запускається до всіх `Test` — почати довгу роботу паралельно (як winget) |

Оцінка: кожна знахідка забирає відсоток від того, що лишилося: критична 40% (і оцінка не вище 39), висока 15%
(не вище 79), середня 6%, низька 2%; «інфо» й ігноровані не рахуються. Так оцінка не падає лише через те, що перевірок стало більше.

### Setup — налаштування ПК за рецептами

**Рецепт** — група налаштувань під конкретну задачу, яку можна **перевірити**, **застосувати** або **відкотити**.
**Профіль** — набір рецептів під ширшу задачу плюс кроки, які не автоматизуються.

| Профіль | Для чого | Рецепти |
|---|---|---|
| `new-pc` | базове налаштування нового ПК | `pcie-aspm`, `disk-power`, `fast-startup`, `home-network` |
| `stability` | зависання GPU і дисків | `pcie-aspm`, `disk-power`, `fast-startup`, `event-logs`, `gpu-stability` |
| `security` | захист ядра і Windows | `hvci`, `lsa-protection`, `driver-blocklist`, `uac-default`, `defender-pua`, `asr-rules`, `network-protection`, `npm-hardening`, `smb1-off`, `rdp-hardening`, `remote-registry-off` |
| `diagnostics` | діагностика крашів | `event-logs`, `diag-tools` |

Рецепти поза профілями: `secure-boot` (покроковий сценарій увімкнення в BIOS), `script-host-off` (вимкнути
Windows Script Host), `app-updates` (оновлення програм через winget). Повний список з описами — `Setup.cmd -List`.

**Сценарій** — покрокова інструкція у вкладці рецепта («Увімкнути ping», «ASPM у BIOS»): ручні дії, команди з кнопкою ▶,
умови «якщо попередня команда вдалася / не вдалася», параметри, перезавантаження.

**GUI** — `modules/setup/SetupGui.exe` (пункт трея «Сетап ПК»). Зліва профілі й рецепти з кольором стану, справа — вкладки:
- **Рекомендовані** — що зараз і що треба, підказка до кожного налаштування, кнопки «Перевірити / Застосувати / Відкотити»,
  ручні кроки. Перевірка йде з правами користувача; UAC запитується лише на «Застосувати» / «Відкотити».
- **Сценарії** — картки кроків зі станом (○ ✓ ✕ –), виводом команд і поясненням «Чому це?»; «Виконати все» йде по кроках
  і зупиняється на ручній дії, перезавантаженні або помилці без запасної гілки. Якщо кроку потрібні права адміністратора,
  вгорі з'являється «Перезапустити з правами» — один UAC на всю сесію.
- **Прогрес** сценаріїв (стани, вивід, параметри) — у `data\setup\progress.json`. Крок-перезавантаження зберігає прогрес,
  додає одноразовий запуск GUI після входу (HKCU `RunOnce`) і перезавантажує ПК (або одразу в BIOS/UEFI);
  після старту вікно відкривається на наступному кроці. Перезавантаження після натискання зараховується автоматично.

**Консоль** — `modules/setup/Setup.cmd` (без аргументів — меню):

```bat
Setup.cmd -List
Setup.cmd -Recipe disk-power            :: перевірка, нічого не змінює
Setup.cmd -Recipe disk-power -Apply     :: старі значення зберігаються в data\setup\ перед зміною
Setup.cmd -Recipe disk-power -Revert    :: повертає саме ті значення, що були до -Apply
Setup.cmd -ProfileName new-pc -Apply    :: усі рецепти профілю
Setup.cmd -Recipe *                     :: аудит ПК за всіма рецептами
```

Код виходу перевірки = кількість відхилень (0 — усе як треба, 255 — помилка запуску), тож аудит нового ПК можна скриптувати.
GUI викликає той самий `Setup.ps1` з `-OutFile <json>`: уся логіка в одному місці, GUI лише показує результат.
`-Apply` і `-Revert` завжди потребують прав адміністратора (`Setup.cmd` сам запитує UAC).

Карантин (для хвостів з аудиту): `Setup.cmd -Quarantine` — список сесій, `-Restore <сесія>` — повернути на місце,
`-Purge <сесія>` — видалити остаточно (не раніше ніж через 30 днів).

**Новий рецепт** — файл `modules/setup/recipes/<назва>.ps1` (UTF-8 з BOM), що повертає хеш-таблицю:

| Поле | Що це |
|---|---|
| `Title`, `Description` | назва й опис для списку |
| `Items` | налаштування (типи нижче) |
| `Steps` | кроки на вкладці «Рекомендовані» (формат кроку нижче) |
| `Reboot` | `$true`, якщо після застосування потрібне перезавантаження |
| `Tabs` | сценарії: `@{ Id; Title; Description; Params; Steps }` |

Крок — рядок (ручна дія) або хеш-таблиця:

| Поле | Що робить |
|---|---|
| `Text`, `Hint` | що зробити; пояснення «Чому це?» |
| `Run` | команда PowerShell для кнопки ▶; вивід показується під кроком |
| `Expect` | regex: крок успішний, лише якщо вивід йому відповідає (інакше рахується лише код виходу / помилки) |
| `If` | `'ok'` / `'fail'` — крок діє, лише якщо попередня команда вдалася / не вдалася; інакше пропускається |
| `Open` | що відкрити кнопкою «Відкрити ↗» (`devmgmt.msc`, `ms-settings:…`, `control.exe /name …`) |
| `Reboot` | `'restart'` або `'firmware'` (одразу в BIOS/UEFI) |
| `Admin` | `$true` — команді потрібні права адміністратора |
| `Confirm` | текст підтвердження перед запуском |

Параметри сценарію: `Params = @(@{ Name = 'IP'; Title = '…'; Default = '…'; Pattern = 'regex'; Hint = '…' })`.
У `Text` і `Run` пишіть `{IP}`: у команду значення підставляється як рядок у лапках, тож його не можна «виконати».

Типи пунктів (`Kind`):

| Kind | Поля | Значення |
|---|---|---|
| `Power` | `Sub`, `Setting` (аліас або GUID), `Power` = `AC`/`DC` | індекс/число в поточній схемі живлення |
| `FirewallRule` | `Name` — **не** `DisplayName`, він локалізований | `'True'` / `'False'` |
| `Registry` | `Path`, `Name`, `Type` (типово `DWord`) | дані або `'<absent>'` (відкат видалить значення) |
| `Custom` | `Get = { ... }`, `Set = { param($value) ... }` | будь-яке, що серіалізується в JSON |

Кожен пункт має `Id` (за ним зіставляється бекап), `Title`, `Desired`, `Hint` (пояснення в GUI) і за бажанням
`Labels = @{ 0 = '…' }` для виводу значень.

**Новий профіль** — `modules/setup/profiles/<назва>.ps1`: `@{ Title; Description; Recipes = @('…'); Steps }`.
Приклади — у `recipes/` і `profiles/`.

## Збірка

```bat
build.cmd
```

Іконка «Вибитий піксель»: вихідний знак — `assets/deadpixel.svg`, готові Windows ICO містять розміри 16–256 px.
Після зміни геометрії або кольорів у `assets/Build-Icons.ps1` перегенеруйте іконки через
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File assets/Build-Icons.ps1` і виконайте `build.cmd`.
У треї помаранчевий піксель означає звичайний стан, жовтий — попередження, червоний — новий непереглянутий збій.
Кадри 16–64 px записані як 32-бітний BMP, 128/256 — як PNG: `System.Drawing.Icon` у .NET Framework показує PNG-кадри як шум.

**Ярлики** — «Налаштування → Ярлик на робочому столі / у меню «Пуск»» або `DeadPixel.exe --shortcuts` (обидва одразу).
Ярлик відкриває панель; якщо DEADPIXEL уже працює, повторний запуск лише показує її в наявному екземплярі.

## Релізи

Готові збірки — на сторінці [Releases](https://github.com/SamuiRo/DEADPIXEL/releases): інсталятор `DEADPIXEL-X.Y.Z-setup.exe`
(для поточного користувача, без прав адміністратора) або `DEADPIXEL-X.Y.Z-portable.zip`.

Як випустити нову версію:
1. Змінити номер у `VERSION` і описати зміни в `CHANGELOG.md` у розділі `## [X.Y.Z] - дата`.
2. Закомітити, поставити тег і відправити: `git tag vX.Y.Z` → `git push` → `git push --tags`.
3. GitHub Actions (`.github/workflows/build.yml`) збере exe, інсталятор, zip, `SHA256SUMS.txt` і опублікує реліз
   з текстом із `CHANGELOG.md`. Якщо тег не збігається з `VERSION`, реліз не створиться.

Той самий пакет локально: `powershell -NoProfile -File tools\Package.ps1` → `dist\`
(інсталятор — лише якщо встановлено [Inno Setup 6](https://jrsoftware.org/isinfo.php), інакше тільки zip).
Кожен коміт у `master` і кожен PR GitHub теж збирає й перевіряє синтаксис скриптів (PowerShell і `linux/audit.sh`).

## Вимоги

- Windows 10 1607+ або Windows 11 (.NET Framework 4.6+ вже є в системі).
- Дані GPU — лише для NVIDIA (через `nvidia-smi`); без нього програма пише лише CPU.
- Температура CPU — якщо запущено LibreHardwareMonitor.
- Аналіз дампів — WinDbg (`winget install Microsoft.WinDbg`); кнопка в програмі встановить його.

## Ключі запуску

`--show` — відкрити панель, `--settings` — налаштування, `--page=Диски` — потрібна вкладка (внутрішній ключ; з англійським інтерфейсом працює й підпис: `--page=Disks`).
`--shortcuts` — створити ярлики на робочому столі й у меню «Пуск».
`--remove-traces` — тихо прибрати сліди поза папкою програми (автозапуск, ярлики, розклад аудиту).
Службові (запускаються самі з UAC): `--analyze <dump>`, `--smart`, `--copydumps <dir>`.

## Видалення

- **Інсталятор** — «Програми» у Windows або «Налаштування → Видалити DEADPIXEL…»: деінсталятор прибирає програму,
  автозапуск, ярлики й розклад аудиту, а про зібрані дані перепитує.
- **Portable** — «Налаштування → Видалити DEADPIXEL…» (або `DeadPixel.exe --remove-traces`): прибирає автозапуск,
  ярлики й завдання Планувальника, перепитує про дані; після цього лишається видалити папку програми.
- Запис чужої копії DEADPIXEL (з іншої папки) не чіпається. Зміни, внесені рецептами Setup, — це налаштування
  Windows, вони лишаються: відкотіть їх у «Сетапі ПК» до видалення, якщо потрібно.
- Разом із даними зникає й карантин: якщо там є прибране, яке ще може знадобитися, спершу відновіть його.

## Мова

Інтерфейс, аудит, рецепти Setup, звіти й інсталятор — українською або англійською.
«Налаштування → Мова»: **Системна** (українська, якщо мова Windows українська, інакше англійська), **Українська**, **English**;
після зміни програма пропонує перезапуститися. Значення зберігається в `data\settings.ini` (`Language=system|uk|en`).
Скрипти беруть мову звідти ж або з ключа `-Lang uk|en` (`Audit.ps1 -Lang en`, `Setup.ps1 -Lang en`, `DeadPixel.ps1 -Lang en`).
Нові тексти в скриптах пишіть парою: `T 'українською' 'in English'` (`modules/common/Lang.ps1`), у C# — `L.T("…", "…")`.

## Дані та приватність

Усе, що програма збирає, лежить у `data/` поруч з exe (або в `%LOCALAPPDATA%\DeadPixel`, якщо туди писати не можна), звіти — у `reports/`.
Обидві папки в `.gitignore`: там назви ваших програм, серійні номери дисків, ім'я ПК.
Нічого не надсилається в мережу, крім завантаження символів Microsoft під час аналізу дампу і перевірки оновлень
програм через winget в аудиті. Аудит читає лише назви й адреси (сайтів, файлів, змінних) — паролі, токени й ключі
у звіт не потрапляють.
